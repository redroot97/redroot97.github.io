jamf binary tampering

Hijacking macOS MDM agents by replacing the JAMF binary with a transparent wrapper.

macos mdm bypass red team 2026.01

// what is JAMF

JAMF Pro is the most widely deployed MDM (Mobile Device Management) solution for macOS in enterprise environments. It manages everything from software deployment and configuration profiles to security policies and compliance enforcement. The agent binary sits at /usr/local/jamf/bin/jamf and runs as root.

When JAMF needs to enforce a policy, push a configuration, or run an inventory check, it invokes this binary. The management server trusts that this binary is the legitimate JAMF agent. But nothing stops an attacker with root access from replacing it.

// the attack surface

The JAMF binary path is predictable and well-documented. On a managed Mac, it's always at /usr/local/jamf/bin/jamf. The binary is a standard Mach-O executable with no integrity verification beyond what the filesystem provides. There's no code-signing check at runtime by the JAMF framework itself, and the management server identifies the agent by its network communication, not by validating the binary hash.

Root cause: the JAMF agent trusts its own binary path. If you can write to that path, you control the agent. On a compromised machine with root, the attacker already has write access to /usr/local/jamf/bin/.

// how the tampering works

  1. Back up the original binary - move the real jamf to a hidden location like /usr/local/jamf/bin/.jamf.real.
  2. Drop a wrapper script - place a shell script (or compiled binary) at the original path that intercepts all calls.
  3. Log and forward - the wrapper logs every command and argument it receives, then passes the call through to the real binary so JAMF operations continue normally.
  4. Selective interception - optionally modify, block, or inject responses for specific JAMF operations.

what the wrapper sees

[JAMF Server] | | "run policy -id 42" v [/usr/local/jamf/bin/jamf] <-- now the wrapper | | logs: "policy -id 42 at 2026-04-10T14:22:01" | can modify, block, or pass through v [/usr/local/jamf/bin/.jamf.real] <-- original binary | | executes normally v [JAMF Server] <-- sees normal response, no anomaly

// what you can intercept

Once the wrapper is in place, every JAMF operation passes through it. This includes:

  • Policy execution - see what policies the server is pushing, modify them before execution, or silently drop security-related ones.
  • Inventory collection - tamper with hardware/software inventory data reported back to the server. Make the compromised machine look compliant.
  • Configuration profiles - intercept profile installations. Block security profiles while letting others through.
  • Software deployment - see what packages are being pushed. Swap binaries. Inject payloads into legitimate software deployments.
  • Check-in traffic - monitor when the machine checks in with the server, what data it sends, and what commands come back.

// persistence value

This technique doubles as a persistence mechanism. The wrapper survives JAMF policy runs because JAMF uses its own binary to execute policies - which is now the wrapper. Even a "reinstall JAMF agent" policy would be intercepted by the wrapper before it could replace it.

The wrapper can also hide itself from JAMF inventory. When the server requests the binary hash for compliance, the wrapper returns the hash of the original binary instead of its own.

// detection

This is a post-exploitation technique that requires root. Detection focuses on filesystem integrity and behavioral anomalies:

  • File hash monitoring - compare the hash of /usr/local/jamf/bin/jamf against the known-good JAMF binary hash. This is the most reliable detection.
  • Mach-O header check - the real JAMF binary is a compiled Mach-O. If it's been replaced with a shell script, the file type changes.
  • File modification timestamps - monitor mtime/ctime on the JAMF binary. Legitimate JAMF updates change these, but so does tampering.
  • Process tree analysis - the real jamf binary forks differently than a wrapper script. Look for bash or sh as a parent of jamf operations.
  • Endpoint telemetry - EDR tools that monitor /usr/local/jamf/bin/ for file writes will catch the swap in real time.
Blue team note: the simplest detection is a cron job or launch daemon that periodically hashes the JAMF binary and alerts if it changes outside of a known JAMF upgrade window.

// compile and run

The POC is a single Swift file. Compile with swiftc (included with Xcode Command Line Tools): 

swiftc jamf-tamper-poc.swift -o jamf-tamper-poc
sudo ./jamf-tamper-poc

The POC backs up the original binary, drops the wrapper, and demonstrates interception of a JAMF policy run. Cleanup instructions are included in the repo README.
